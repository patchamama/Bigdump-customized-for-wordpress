## Specs
S1: "agrega posibilidad de hacer un reporte de todo el estado del sitio si uno desea y para ello agregar un tab de Reporte que permita guardar todo el estado completo para audit del sitio, con características de wordpress, php, del sitio web, seguridad, versiones, errores encontrados clasificados por niveles de riesgo (crítico, warning, ok), version de php usada y de mysql, todo lo que se pueda"
S2: "deseo que toda esta información se pueda descargar en un json"
S3: "ese json se pueda enviar a un sitio de github privado, usando la url del repo de github y además el token y en una rama llamada wordpress-report (ese nombre es editable también y se pudiera cambiar) debe de ponerse el reporte del sitio completo en un json con el nombre del dominio usado para wordpress, algo como dominio-name.json en la rama del reporte."

S4: "debe de guardarse en localhost todas las contraseñas y valores tecleados encriptados por la contraseña que se uso para entrar en la app y así cuando se vuelva a abrir la app deben de restaurarse estos valores en el frontend."
S5: "si, localstorage"

S6: "a lo aquí implementado, genera una url del sitio actual llamando a este script: cms_tool.php con un token que permita que sea llamado desde cualquier app y que devuelva un json con toda la información del estado del sitio, esto permitiría a una app externa obtener un informe del estado actual del sitio pero necesitaría el token para poder tener esa información."
S7: "Adicionalmente deseo que se agregue una opción de actualización de wordpress a la última versión disponible, y para ello debe de usarse la opción del sandbox que permitiría usar la instalación existente o hacer una nueva instalación con todos los recursos existentes actualizando el wordpress y testeando sí todos los plugins son compatibles en ese entorno, proponer hacer copia de seguridad antes de todo por sí se desea regresar a la version anterior, testea uno a uno sí los plugins son compatibles, sí los assets están presentes en la actualización, sí no hay error 500 por el htaccess, sí las variables de php no dan problema y todas las cosas clásicas que suelen fallar tras actualización. Sí todo funciona bien, dar el ok, y proponer tras backup del sitio completo usar la actualización como el sitio principal o moverlo al sitio actual. Si algo falla, dar tips de como corregirlo."
S8: "Mejora todo el script de cms_tools.php para que los comentarios interno estén en inglés y no en castellano."
